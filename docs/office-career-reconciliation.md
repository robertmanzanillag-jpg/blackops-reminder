# Preserved legacy career scores

This is an operator-only, pure reconciliation primitive. There is no automatic migration, storage writer, route, provider call, execution admission or qualification decision.

The existing scalar battery is not a complete history of verified outcomes. The repository correction `fc7f319199725c20725110f9e32a47a8215ff55e`, committed 2026-11-06 at 20:31:42 UTC, required distinct evidence IDs and attributable failures. Its commit time is a code-history boundary, **not** a claimed production deployment timestamp. Before that change, some observation cycles could affect scores without such a ledger.

`reconcileLegacyCareer` accepts an exact current career digest, generation and expected canonical state revision. A trusted caller callback must verify that same owner-bound career from the locked canonical row and return a recent read receipt. The function accepts only old-format records with observed cycles and no `evaluatedEvidenceIds` field. A pre-correction evaluation timestamp is labelled an unverifiable old score; records without any last evidence/evaluation and with old hire/retirement counters are labelled unversioned observations. Neither classification proves agent misconduct, an infrastructure cause or historical success. Modern exhausted careers with an evidence ledger are excluded, including an empty ledger.

The returned ledger uses proposed namespace `office_career_reconciliation_v1` in existing owner-bound persistence. Each entry retains the entire original career, its canonical digest, operator audit ID, read receipt, correction revision and explicit `batteryAdjusted=false`, `promotionGranted=false`, `fullRoleQualified=false`. The current career receives only a typed `needs_scope_qualification` marker. Battery, generation, points, counters, skills and original memory are not reset or reconstructed.

Integration must hold the council owner advisory lock, reread/lock the current row, verify its version/digest and commit the immutable ledger plus career marker atomically. It must save a protected pre-change backup and validate both records after commit. Applying only one half is invalid. This module creates no table and performs no writes. Repeated reconciliation of the same archived career is idempotent; a changed protected score, generation or contradictory marker fails closed. The complete original stays immutable while ordinary later order notes or training memory can evolve.

Marked careers are excluded from future probe scoring/retirement and order-based life, points or skill rewards. This preserves the disputed scalar; it does not rehabilitate an agent. Runtime admission and UI must recognize the marker before any operational application: a positive old battery is not qualification, and narrow triage life is never substituted for whole-career life. No admission bypass is implemented here. Qualification requires a separate, named capability and real evidence; whole-role permissions and promotions remain blocked until an explicit qualified process exists.

No current career is selected automatically. In particular, positive legacy scores are not batch-reclassified merely because the ledger is absent. The first operational use, if approved, should target only explicitly reviewed exact records. The immutable ledger has a 100-record / 4 MB cap with no pruning. Its contents are private owner history, not a public health response.
