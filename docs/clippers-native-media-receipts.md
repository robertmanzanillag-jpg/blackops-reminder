# Native Metricool media and external schedule observations

The native import path does not upload or schedule media. An existing authorized upload operator can deposit an owner-only JSON receipt at `reports/clippers-daily-learning/native-media-imports/<assetId>.json`. A reviewed prepare packet explicitly selects `mediaProvider: "metricool"`; packets without this selector retain the existing Drive behavior. No new credentials, OAuth connection or publishing flags are introduced.

The receipt must have `schemaVersion: 1`, `provider: "metricool"`, `kind: "metricool_native_media_receipt"`, `status: "ready"`, the exact `assetId` and destination, `renderReceiptSha256`, `renderRequestSha256`, `sha256`, `sizeBytes`, `mediaUrl`, `resource`, `verifiedAt`, `verification: "anonymous_exact_bytes_sha256"`, `authorizedManifestSha256` (SHA256 of JSON.stringify of the complete prepare packet), `paidSpendAllowed: false` and `paidSpendUsd: 0`. `resource` identifies an actual returned S3 bucket/key or `{kind: "metricool_cdn_url", url}` for a verified native CDN URL. No Drive file ID is fabricated. Only the actually observed queryless `https://static.metricool.com/video/<owner>/<YYYYMM>/<name>.mp4` URL shape is admitted. Preparation checks request/packet/render/source/target rights as before, then anonymously streams and hashes the exact native bytes before writing provider-specific evidence and queue input. A failed import never falls back to a new upload. The initial receipt is immutable; live byte verification is repeated rather than changing the receipt digest to refresh its age. Rights freshness and expiry remain independent and unchanged.

`reconcileExternalMetricoolSchedule` observes a post already scheduled outside the pipeline. Its input is `{destination, metricoolId, scheduledAt, caption, mediaUrl, sha256, sizeBytes, origin?}` and binds to the private prepare packet, request and immutable render receipt. Supply `"external_metricool_api"` when the original scheduling evidence shows a Metricool API call. Use `"external_owner_ui"` for an owner-UI schedule. Omitted origin retains the owner-UI default. The observer validates local bytes, streams the public bytes anonymously, and confirms the exact schedule with the provider GET. Past schedules can be recorded as observations. The ledger records the schedule confirmation and leaves publication and performance unmeasured.

The external observation is durable before a reusable native media receipt is written, under the shared scheduler lock. Re-observation keeps the original ledger row, digest and evidence timestamp. Origin changes for an existing schedule are rejected. A matching typed native-media import keeps its original bytes and origin. Office counts owner-UI and Metricool API observations under their respective origins. These observations grant no pipeline delivery or career credit. Both daily and weekly dispatch paths consult it, including exact asset/media identity and the verified original-source interval. New IDs, crops, reencodes or URL aliases cannot replay the same source interval. Missing interval proof retains the conservative source URL guard. Corrupt or contradictory dispatch ledgers hold rather than becoming an empty list. Report projection leaves unobserved accounts unknown and partial external observations without complete daily coverage have an unknown shortfall.

The observer CLI accepts only `--observe <private-external.json> --asset <id>` and the existing `CLIPPERS_WORKSPACE_ROOT` / `CLIPPERS_CONFIG_ROOT` metadata pointers. It performs no provider writes. It must not be run as a shortcut for publishing or before independent review and installation.

Calendar accounting reserves known `PUBLISHING` rows. A `PUBLISHED`/`POSTED` row with an exact owned public post URL can also reserve capacity while analytics lags; its original calendar hour is occupied, but no publication timestamp or metric completeness is invented. Once the exact platform ID appears in analytics it is counted once, using the measured publication time. Unknown statuses, wrong owners, conflicting identities, incomplete pagination and opaque provider attribution remain held.

Validation uses synthetic local FFmpeg media and fake transports. This change does not prove any real upload, booking or publication; those require separate actual provider GET and public-byte receipts. Rollback restores the prior scripts together; keep private external observation files as audit/no-replay evidence and do not resume dispatch with code that ignores them.
