# Radio parser qualification

The opt-in internal worker includes a versioned deterministic adapter comparing the installed Radio description parser against an approved implementation supporting whole-line, adjacent-hour PM ranges. The existing parser remains unchanged. Simple assignments continue through that same parser. Deployment and controlled worker restart are required before activation.

The trusted, fixed oracle contains three independent format families: compact ranges, explicit time ranges and HTML ranges. Each includes legacy inputs or empty/negative cases. Qualification requires strictly better exact slot assignments in every family and no loss on a previously correct case. Reading modules, changing a name or receiving a model's self-assessment cannot qualify the candidate.

The trial retains both implementations' actual outputs, expected assignments and structural preprocessing counters. It also measures elapsed processing time separately. The bounded parser contract allows at most 20,000 input characters and a maximum measured second per family; this is a latency ceiling, not a claim that the candidate is faster. There are no provider invocations or API charges. Existing reviewer comparison requirements are unchanged.

This qualification covers parsing this format only. It does not prove DJ availability, current calendar synchronization, permission to contact anyone, publishing readiness or better general reasoning. Unknown versions and oversized inputs fail closed; unsupported formats retain the existing parser behavior and are not newly qualified.

Only the active baseline incumbent, with the same career generation and no running/unknown lease, can receive this skill update. It keeps the same person and generation. Three independent format-family assessments represent one deterministic trial, not three days of production performance. This gate never fills a vacancy, promotes a replacement, or changes reviewer graduation requirements. A specific incumbent training entry records these actual assessments; reading modules alone cannot apply the policy.

The policy update, complete qualification receipt and admitted Radio execution lease commit together in the existing owner-scoped Postgres council. The first verified saved-record report is linked separately by run ID, timestamp and artifact digest. Source failure produces a blocked report without life penalties or a claim of execution success. Qualification history remains separate from bounded daily-report retention. The normal Radio analysis API resolves the same saved implementation version; other users cannot read the owner's private policy state.

With `OFFICE_INTERNAL_WORK_ENABLED=true`, Radio adds at most one report per UTC day alongside CEO and assistant. Its source is at most 200 saved Google calendar Radio/Black Room rows, with full counts, newest saved dates first and descriptions bounded to 2,000 characters. Raw timestamp meaning is preserved; the report does not claim those rows are upcoming or freshly synchronized. No recurrence expansion, calendar sync, DJ contact, publishing, API model call or budget increase occurs.

Descriptions above the 2,000-character stored-snapshot limit block the Radio report rather than silently truncating parser input. That source limitation remains visible and does not reduce life.

Rollout: deploy the compatible web parser first, drain the previous worker, verify the exact revision/owner protocol and restart through the reviewed operator procedure. Do not let an older worker parse new Radio artifacts. This change does not restart services or modify local worker credentials automatically.

Evidence digests now sort object keys before hashing because PostgreSQL JSONB changes key order. Existing Radio receipts remain valid only when their stored digest matches the exact original writer shape reconstructed from the trusted oracle and validated timing fields. Their attestations are not rewritten. Internal report schemas already reconstruct their original field order before validating existing report hashes.

`recoverRadioReadOnly` is an operator-only recovery function, with no HTTP route or automatic caller. After independently pausing and draining the worker and retaining a private backup/audit record, an operator may reconcile one expired Radio job with its exact prior fence. The prior job and lease remain recorded as an unknown interrupted attempt. A new fence and fresh read of canonical saved records must complete before first-execution evidence is linked. No old attempt is declared successful, no provider is invoked, and no automatic replay or life scoring occurs. Mismatched leases, existing artifacts, active work, changed holders, and repeated admissions fail closed.
