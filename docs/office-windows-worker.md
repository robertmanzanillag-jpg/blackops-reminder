# Windows reviewer worker

Scheduled launcher paths must use local drive absolute paths, such as `C:\Office`; UNC/network paths, percent expansion, quotes and trailing separators are rejected. Explicit upgrade mode fails if the owned task is missing; it never creates a replacement registration.

The scheduled action now uses Windows' native GUI `wscript.exe` to run the small reviewed `.vbs` launcher, which starts Node hidden and waits for its exit. It does not run a PowerShell script or change/bypass PowerShell execution policy. Task Scheduler's `Hidden` setting alone would not hide a Node console. The Node wrapper independently verifies the configuration ACL using a fixed read-only `Get-Acl` command; the path is passed as an environment value, never interpolated into code. Windows Script Host must be available under the machine's existing policy; if blocked, stop rather than weaken policy.

Prepared launcher; no task is installed by these files alone. This runs only the owner-scoped repository reviewer and its bounded academy, not all business agents. The Windows PC must remain powered on, awake, connected and signed into the configured user. Locking the screen is compatible; signing out or shutting down stops execution. No Windows password is stored.

Use the reviewed checkout and its installed dependencies, a trusted absolute `node.exe` path, and an owner-protected configuration file outside the repository. Do not put credentials in command arguments, repository files or task descriptions. The launcher reads the file only at runtime; it never evaluates its contents as PowerShell or JavaScript. Restrict that file's ACL to the current user and administrators before rollout.

Required configuration names: `DATABASE_URL`, `DEFAULT_USER_ID`, `OPENAI_API_KEY`, `OFFICE_OPENAI_MODEL`, `OFFICE_OPENAI_MONTHLY_TOKEN_LIMIT`, `OFFICE_EXPECTED_WEB_REVISION` (the exact verified 40-character web commit). Optional: `OFFICE_OPENAI_MAX_OUTPUT_TOKENS`, `GITHUB_TOKEN`, and the three academy/preparation/benchmark-promotion flags documented in the OpenAI rollout guide. Unknown and duplicate keys are refused. Model, budget and owner must be explicit. Academy flags default off. Repository-local environment files are refused so the existing application environment loader cannot silently select another database or credential. Node 22 or newer is required. Both PowerShell entrypoints reject inherited Node hooks/TLS overrides and reject configuration ACLs granting access beyond the current user, SYSTEM and Administrators.

Run `script/office-windows-install.ps1` with `-NodePath`, `-RepoPath`, and `-ConfigPath` (all absolute). Its default is validation only, including read-only database schema and owner checks. `-Apply` registers the reviewed task; it does not bypass preflight and does not start an immediate job. The task runs at login and checks every five minutes for recovery; `IgnoreNew` keeps the continuous worker single-instance. It runs with the current user's interactive token and limited privileges, in a hidden window. It never replaces an existing task. An existing exact owned registration is reported unchanged; mismatches require explicit inspection.

There is no paid host or system service installation. API token reservations and unknown-result fences remain in the shared database. Task Scheduler's last result and the office's persisted runs provide evidence; hidden child output is discarded to prevent private payloads entering log files. A failed preflight starts no provider and performs no migrations. A later task trigger is a worker recovery, not permission to repeat an uncertain job.

Normal wrapper termination forwards termination to its owned child. Forced Task Scheduler/process-tree termination and recovery still require a real Windows rollout test before unattended use; killing a provider call can leave an unknown result, which must retain its database fence and token reservation. The installer validates the exact existing task's privilege, logon, trigger and single-instance settings and refuses altered registrations.

For the old PowerShell task action, disable the task first. The reviewable installer supports `-UpgradeOwnedAction` only when the existing task has the exact owner-derived name, marker, SID, old action arguments, working directory, limited interactive principal and approved triggers/settings. Its default remains dry run. `-Apply -UpgradeOwnedAction` changes only that disabled task's action; enable separately after readback and a harmless hidden-launch test. Unrelated or modified tasks are never upgraded. If policy blocks the installer file, use an already-authorized administration interface to apply the same reviewed task-action change; do not relax policy or use execution-policy bypass flags. The old `.ps1` launcher is retained solely to identify previous registrations and is not the new scheduled entrypoint.

Rollout remains blocked until the compatible web release is deployed, old writers are drained, and the shared owner/database identity is verified. Preflight calls `assertOfficeProtocolReady` against the durable operator-verified rollout record and dedicated council state; a configuration flag alone cannot bypass it. The worker always uses `AGENT_COUNCIL_STORAGE=postgres`, keeps a continuous heartbeat and exits after repeated failures using fail-fast mode. The old web version can discard academy reservations or expose new internal state. Do not install against the editor's empty database or placeholder owner. Stop/disable the owned task before code/configuration maintenance; preserve database reservations and execution history. Restart only after reconciling uncertain work. No automatic task deletion, credential creation or deployment is included.
