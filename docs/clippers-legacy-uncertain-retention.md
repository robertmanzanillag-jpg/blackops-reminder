# Legacy uncertain deliveries

A missing current Metricool calendar row does not prove that an earlier attempt was never accepted, published, removed or changed. Before a legacy `verification_pending`/`pending_write` post can become `not_found`, the same owner transaction now retains a `legacy_uncertain_delivery_reservation` in the existing global media ledger. It records the exact original source/segment, optional physical provenance, final hash, account, planned time, available attempt/ID/media evidence and an explicit `historically_unresolved`/`noReplay` marker. Missing evidence stays unknown; no execution, cancellation, publication or learning receipt is invented.

Retention is immutable per exact attempt. A stale provider read cannot replace a changed attempt or a newly reconciled status. Missing required source/hash/segment identity, a malformed matching reservation, an overlarge claim or a full5000-entry ledger keeps the post uncertain. Protected reservations cannot be removed by prewrite claim cleanup, same-source upsert or normal tail eviction; required incoming claims fail closed when protected capacity leaves no room. Ordinary historical-entry tailing is unchanged. Reservations continue participating in cross-source/segment/file/account conflicts after the600-post history trim, including the legacy lanes-off final write gate. Known staged asset IDs and exact public media URLs remain pinned while uncertainty remains. The Mac mirror uses the same bounded preservation helper; its existing cloud-owned-brand write refusal remains unchanged.

No production claims or provider records are changed by this PR. Tests reconstruct the three observed public source/segment/hash/planned-time tuples with unknown provider IDs and attempt times; staging IDs and optional physical provenance used in tests are explicitly synthetic. Existing already-`not_found` history is not automatically backfilled or treated as proof of nonexecution.

## Operational hold and targeted read-only plan

This release intentionally adds retention only. Neither a normal publisher run nor `growthOnly` is a safe targeted reconciliation command: the shared run can change state and perform other housekeeping, and the normal mode can publish eligible work. No new execution authority or unauthenticated repair endpoint is added.

A future bounded owner-authorized operation must select exact legacy post IDs, obtain a fresh complete calendar through the existing trusted provider adapter, retain exact native media/caption/date/UUID identity proof, and establish that the relevant old writers are quiescent before interpreting an observation. Current absence alone must continue to reserve the historical source and prohibit replay; the three attempts with no IDs/UUIDs or never-write evidence remain unresolved. A proposed metadata refresh of a known held draft must independently prove the same UUID, exact caption/time/media bytes and ID replacement chain from fresh provider read-back. This PR does not refresh the known held draft, cancel schedules, guess IDs or claim that those operational proofs exist.

Rollback: revert this code change while keeping publishers and Mac writes held. Preserve any reservations already retained; deleting a protective reservation is not rollback evidence or permission to retry a historical attempt.
