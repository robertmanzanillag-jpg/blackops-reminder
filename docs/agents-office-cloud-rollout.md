## Execution boundaries

- The web process persists accepted tasks only in cloud mode. A separate explicitly enabled worker claims durable PostgreSQL jobs. There is no local-file fallback in production.
- Schema SQL is exported by `createOfficeCloudSchemaSql()`. It is not applied automatically. Review and apply it through an approved migration, then verify actual PostgreSQL concurrency/locking before launch.
- Build emits `dist/office-worker.cjs` and the prepared `dist/office-cloud-schema.sql`. An optional dedicated Linux setup runs `npm run office:cloud` to supervise the web launcher and worker together. Install the official Claude Code CLI separately on the intended execution host. The normal web deployment does not install the CLI, execute the office SQL migration, or start the queue worker.
- The cloud supervisor requires Linux, `OFFICE_WORKER_ENABLED=true`, and `OFFICE_HOSTING_MODE=reserved-vm`. It terminates its own web/worker process groups on failure or shutdown, with bounded TERM/KILL cleanup and no task restarts. Hosting mode is an operator declaration; actual Reserved VM configuration and fresh heartbeat must still be verified. `OFFICE_RUNTIME_MODE=postgres` prevents a local journal in this cloud setup.
- Authenticate the unmodified official Claude Code CLI on the actual execution host using the owner's subscription. A PC login is not cloud authentication. The default mode uses the CLI's own sign-in. For an automated host, explicit `OFFICE_CLAUDE_AUTH_MODE=subscription-token` permits the documented `CLAUDE_CODE_OAUTH_TOKEN` channel, generated by the owner through Anthropic's official `claude setup-token` flow and entered privately by the owner in the execution host's secret manager. Do not collect credentials in the office UI, copy the PC's session, commit credentials, modify the CLI binary, or introduce a new paid API key. Authentication status confirms configuration; only a successful recorded result proves execution. Official reference: https://code.claude.com/docs/en/env-vars.
- After the KONG read bridge is deployed, the owner configures the same dedicated `KONG_OFFICE_READ_TOKEN` in both apps' private secrets. It grants only the operations and city health reads. The 3D city roster uses the public KONG directory independently; a visible avatar alone is not work evidence. This audit does not start city jobs or WhatsApp readers.
- `OFFICE_KONG_AUDIT_SCHEDULE_ENABLED=true` enables the supervisor in the persistent worker after a successful KONG capability check. PostgreSQL deduplicates scheduled reads in four-minute windows. The office shows points from the latest verified snapshot, with deductions for recorded failures or overdue work. Missing evidence is unscored. Scheduled audits do not call Claude or change KONG data.
- `DEFAULT_USER_ID`, valid owner authentication, `PUBLIC_APP_URL`, PostgreSQL access, and the existing GitHub connection are required. Never expose these credentials in browser storage or responses.
- Claude runs without shell/file/network tools, hooks, or MCP extensions. PR approval requires the same current head and full diff hash, a fresh completed session, a passing verdict, and no findings. A newer blocking verdict revokes an earlier pass.
- Worker liveness and provider capability timestamps come from the actual execution host. Unknown/interrupted executions are not automatically retried. Permanent idempotency keys prevent duplicate dispatch.
